## 快速开始

### 环境要求
- Docker Desktop 已启动
- 项目已通过 `docker-compose up -d` 启动
- Python 3.11+ (如果直接运行脚本)

### 三种使用方式

#### 方式1：Windows批处理脚本（推荐新手）
```bash
# 在项目根目录直接双击或命令行运行
migrate.bat status
migrate.bat create "添加新字段"
migrate.bat upgrade
```

#### 方式2：Linux/Mac Shell脚本
```bash
# 给脚本执行权限
chmod +x migrate.sh

# 运行命令
./migrate.sh status
./migrate.sh create "添加新字段"  
./migrate.sh upgrade
```

#### 方式3：直接使用Docker命令
```bash
docker-compose exec backend python scripts/migrate.py status
docker-compose exec backend python scripts/migrate.py create "添加新字段"
docker-compose exec backend python scripts/migrate.py upgrade
```

**步骤2: 创建迁移**
```bash

```

**步骤3: 检查生成的迁移文件**
生成的迁移可能是：
```python
def upgrade() -> None:
    op.alter_column('users', 'username',
               existing_type=sa.VARCHAR(length=50),
               type_=sa.String(length=100),
               existing_nullable=False)

def downgrade() -> None:
    op.alter_column('users', 'username',
               existing_type=sa.VARCHAR(length=100),
               type_=sa.String(length=50),
```

- 确保现有数据中没有超过50字符的用户名
- 如果有，需要先清理数据或调整迁移逻辑

## 常见场景处理

### 场景1: 添加非空字段到已有数据的表

**问题**: 向已有用户的表中添加非空字段会失败

**解决方案**: 分两步迁移
```python
# 第一步: 添加可空字段并设置默认值
def upgrade() -> None:
    op.add_column('users', sa.Column('phone', sa.String(20), nullable=True))
    # 为现有用户设置默认值
    op.execute("UPDATE users SET phone = '' WHERE phone IS NULL")

# 第二步: 修改为非空
def upgrade() -> None:
    op.alter_column('users', 'phone', nullable=False)
```

### 场景2: 重命名字段

```python
def upgrade() -> None:
    # 重命名字段
    op.alter_column('users', 'old_field_name', new_column_name='new_field_name')

def downgrade() -> None:
    op.alter_column('users', 'new_field_name', new_column_name='old_field_name')
```

### 场景3: 删除字段（安全方式）

```python
# 第一步迁移: 标记字段为废弃（添加注释）
def upgrade() -> None:
    op.alter_column('users', 'deprecated_field', comment='DEPRECATED - will be removed')

# 等待几个版本后，第二步迁移: 真正删除
def upgrade() -> None:
    op.drop_column('users', 'deprecated_field')
```

## 故障排除指南

### 错误1: "数据库连接失败"

**错误信息:**
```
❌ 数据库连接失败: could not connect to server: Connection refused
```

**解决步骤:**
```bash
# 1. 检查Docker服务
docker-compose ps

# 2. 如果postgres服务未运行
docker-compose up -d postgres

# 3. 等待服务启动
sleep 10

# 4. 检查服务日志
docker-compose logs postgres

# 5. 重启所有服务
docker-compose restart
```

### 错误2: "迁移文件语法错误"

**错误信息:**
```
sqlalchemy.exc.ProgrammingError: (psycopg2.errors.SyntaxError) syntax error at or near "COLUMN"
```

**解决步骤:**
1. 查看最新的迁移文件
2. 检查SQL语法是否正确
3. 如果是自动生成的错误，手动修正
4. 重新运行迁移

**示例修正:**
```python
# 错误的迁移
def upgrade() -> None:
    op.add_column('users', sa.Column('new_field', sa.String(50)))
    
# 修正后
def upgrade() -> None:
    op.add_column('users', sa.Column('new_field', sa.String(50), nullable=True))
```

### 错误3: "模型无法导入"

**错误信息:**
```
ImportError: cannot import name 'SomeModel' from 'src.infrastructure.database.models'
```

**解决步骤:**
1. 检查模型文件是否存在语法错误
2. 确认在`__init__.py`中正确导入了模型
3. 重启后端服务

```python
# backend/src/infrastructure/database/models/__init__.py
from .user import User
from .region import Region
from .player_profile import PlayerProfile
# 确保新模型也被导入
from .new_model import NewModel
```

### 错误4: "迁移版本冲突"

**错误信息:**
```
Multiple head revisions are present for given argument 'head'
```

**解决步骤:**
```bash
# 1. 查看当前迁移状态
migrate.bat history

# 2. 合并分支迁移
docker-compose exec backend alembic merge heads -m "合并迁移分支"

# 3. 应用合并后的迁移
migrate.bat upgrade
```

### 错误5: "数据完整性约束违反"

**错误信息:**
```
IntegrityError: duplicate key value violates unique constraint
```

**解决方案:**
```python
# 在迁移中先清理冲突数据
def upgrade() -> None:
    # 删除重复数据
    op.execute("""
        DELETE FROM users a USING users b 
        WHERE a.id < b.id AND a.email = b.email
    """)
    
    # 然后添加唯一约束
    op.create_unique_constraint('uq_users_email', 'users', ['email'])
```

## 最佳实践

### 1. 迁移文件命名规范
- 使用描述性的名称: "添加用户头像字段" 而不是 "修改用户表"
- 包含操作类型: "添加", "删除", "修改", "重构"
- 保持简洁但信息完整

### 2. 安全的迁移操作
```python
# ✅ 好的做法
def upgrade() -> None:
    # 创建表前检查是否已存在
    if not op.get_context().dialect.has_table(op.get_context().connection, 'new_table'):
        op.create_table('new_table', ...)
        
    # 添加字段前检查是否已存在  
    if not column_exists('users', 'new_field'):
        op.add_column('users', sa.Column('new_field', sa.String(50), nullable=True))

# ❌ 危险的做法
def upgrade() -> None:
    op.create_table('new_table', ...)  # 可能已存在
    op.add_column('users', ...)  # 可能已存在
```

### 3. 数据迁移的处理
```python
def upgrade() -> None:
    # 先修改结构
    op.add_column('users', sa.Column('full_name', sa.String(100), nullable=True))
    
    # 再迁移数据
    connection = op.get_bind()
    connection.execute("""
        UPDATE users 
        SET full_name = CONCAT(first_name, ' ', last_name)
        WHERE first_name IS NOT NULL AND last_name IS NOT NULL
    """)
    
    # 最后设置约束
    op.alter_column('users', 'full_name', nullable=False)
```

### 4. 测试迁移
```bash
# 开发流程
1. migrate.bat create "描述修改"
2. 检查生成的迁移文件
3. migrate.bat upgrade  # 应用迁移
4. 测试应用功能
5. migrate.bat downgrade  # 测试回滚
6. migrate.bat upgrade  # 重新应用
7. git add & commit
```

## 高级技巧

### 1. 批量数据处理
对于大表的数据迁移，分批处理避免锁表：

```python
def upgrade() -> None:
    connection = op.get_bind()
    
    # 分批处理大量数据
    batch_size = 1000
    offset = 0
    
    while True:
        result = connection.execute(f"""
            UPDATE users 
            SET status = 'active' 
            WHERE status IS NULL 
            LIMIT {batch_size} OFFSET {offset}
        """)
        
        if result.rowcount == 0:
            break
            
        offset += batch_size
```

### 2. 条件迁移
根据环境或数据状态执行不同的迁移逻辑：

```python
def upgrade() -> None:
    connection = op.get_bind()
    
    # 检查是否为生产环境
    env = os.getenv('ENVIRONMENT', 'development')
    
    if env == 'production':
        # 生产环境的安全迁移
        op.add_column('users', sa.Column('new_field', sa.String(50), nullable=True))
    else:
        # 开发环境的快速迁移
        op.add_column('users', sa.Column('new_field', sa.String(50), nullable=False, default=''))
```

### 3. 自定义迁移脚本
创建专门的数据清理或初始化脚本：

### 4. 迁移日志和监控
```python
import logging

def upgrade() -> None:
    logger = logging.getLogger('migration')
    
    try:
        logger.info("开始迁移用户表...")
        op.add_column('users', ...)
        logger.info("用户表迁移完成")
        
        logger.info("开始数据清理...")
        connection = op.get_bind()

```

## 紧急恢复程序

### 如果迁移导致严重问题

**立即停止服务:**
```bash
docker-compose down
```

**从备份恢复数据库:**
```bash
# 如果有数据库备份
docker-compose exec postgres psql -U postgres -d flyesports < backup.sql
```

**回滚迁移:**
```bash
# 回滚到问题发生前的版本
migrate.bat downgrade 3  # 回滚3步
```
